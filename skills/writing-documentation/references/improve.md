# Improve existing docs

Use Diátaxis as a guide, not a plan. Improve the docs in small steps, and let the structure follow from the improvements. Avoid both a top-down redesign and a teardown and rewrite: any set of docs, however messy, can be improved one step at a time.

## Work one step at a time

Repeat this loop:

1. Choose one piece: the page you are in, the paragraph the user pointed at, or any page. Start with what is in front of you rather than searching for the worst problem.
2. Assess it, at the scale of a page or smaller: a section, a paragraph, a sentence. Which reader need does it serve, by the compass? How well does it serve that need? What could be added, moved, removed, or changed? Do its language and logic match its type's file?
3. Decide on the single next action that improves it now, such as moving an explanatory paragraph out of a tutorial, retitling a guide, or splitting a page that answers two questions.
4. Do it, and treat it as finished. Commit it as its own change. When the user asked for a set of changes, keep each one separate so they can review each alone.

Then go back to step 1. Each change usually shows you the next one.

## Let the structure grow from inside

Add top-level sections for tutorials, how-to guides, reference, and explanation only when content exists to fill them. Empty sections are the clearest sign of structure imposed from outside. As you improve pages, a group of them will start to demand its own heading; that is when to move them under it.

Keep the docs complete at every step, even though they are never finished. Like a growing plant, they should be useful to readers, healthy in structure, and ready for the next stage at each point.

## Report the work

List each change with the page, what moved or changed, and which type it now serves. List the problems you saw but left for a later step.
