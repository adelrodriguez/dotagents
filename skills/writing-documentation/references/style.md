# Documentation style

These rules apply to the sentences on every documentation page, whatever its type. The `unslop` skill covers wording that applies beyond documentation.

## Write each sentence

- Address the reader as "you", in the present tense. Use "will" only for things that happen later.
- Put the common case first and the exceptions after it.
- Split a sentence longer than about 25 words.
- Leave out "please" in instructions, and "simply", "easy", and "quickly" in procedures.
- Leave out announcements of future work, such as "We will soon support…".

## Write procedures

- Write each step as a command: "Install the component", not "The component must be installed".
- Give each step one instruction.
- Split an instruction longer than about 20 words.
- Use one verb for each action across the docs, such as "start" everywhere rather than "start" in one place and "initiate" in another.

## Format the page

- Make each heading state the point of its section, such as "Pick the mode first" rather than "Modes". Write a task heading as a verb phrase, such as "Create an instance", and a concept heading as a noun phrase.
- Use one h1 per page, and do not skip heading levels.
- Use numbered lists for sequences and bullets for everything else. Introduce each list with a complete sentence, and keep its items parallel.
- Write link text that names the destination, such as the page title. Never write "click here".
- Put code, paths, commands, and symbols in code font. Put UI elements in bold.
- Use the serial comma.
- Say when a list is partial, before the list. Do not end it with "etc."
